# Intake Workflow

## 1. Search and Select Registration

1. Operator searches by crop registration code, farmer name, village, or farmer code.
2. System returns only season-scoped matching registrations.
3. Operator selects the exact registration record.
4. System displays registration card with:
   - farmer details
   - crop, variety, class stage
   - certified area
   - expected yield
   - allowed intake
   - total received
   - pending balance
   - status

## 2. Pre-Entry Validation

System blocks entry if:

- registration does not exist
- status is not `ACTIVE`
- certified area is `<= 0`
- expected yield is `<= 0`
- registration balance is exhausted

## 3. Receipt Header Entry

Operator enters:

- receipt number
- receipt date/time
- vehicle number
- operator remarks

Receipt number is auto-generated by default and editable only by admin.

## 4. Receipt Line Entry

Each line represents one physical intake placement and requires:

- registration linkage
- godown
- stack
- bag count
- bag weight and/or net weight
- quantity in QTL
- moisture percentage
- quality status
- remarks optional

One receipt may have multiple lines if material is physically split across stacks.

## 5. Allocation Engine Execution

For each receipt line:

1. load open compatible lots for same registration and stack
2. sort lots by ascending lot number
3. allocate to existing lot until lot balance is consumed
4. if quantity remains, create next lot and allocate remainder
5. repeat until line quantity is fully allocated
6. ensure no lot exceeds `200 QTL`

## 6. Save Transaction

The API transaction performs:

1. registration lock
2. duplicate receipt check
3. receipt header insert
4. receipt line insert
5. lot create/update
6. allocation insert
7. registration aggregate update
8. audit log insert

## 7. Post-Save Outputs

After successful save:

- show receipt detail
- show allocation breakdown by lot
- offer print inward slip
- expose traceability links to registration, lot ledger, and stack position

## 8. Exception Paths

### Quantity exceeds registration balance

- block save unless admin override policy is enabled

### Existing lot overflows

- auto-split into existing lot balance plus one or more new lots

### Stack changes

- create separate lot continuity under selected stack

### Hold or rejected quality

- prevent mixing with incompatible open lots
